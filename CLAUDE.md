# CLAUDE.md

Guidance for Claude Code (claude.ai/code) when working in this repository. This
is a generalized template: the rules and the shape of the project, not a
walkthrough of the code. Обзор возможностей, инструментов и настроек — в
`README.md`; источник правды по деталям — сам код.

## Что это

MCP-сервер поверх OpenSSH и `~/.ssh/config`: доступность хостов, выполнение
команд, фоновые задачи, правка конфига и чтение документации инструментов через
`llms.txt`. Возможности разложены по независимым роутерам.

## Окружение и команды

Проект на uv, Python 3.13, src-раскладка: пакет `src/mcp_hostops`,
тесты в `tests/`. Не использовать pip и не запускать python напрямую.

```bash
uv sync                          # окружение из uv.lock, включая dev-группу
uv add <pkg>                     # добавить зависимость (--dev для dev-группы)
uv run mcp-hostops     # консольная точка входа
uv run ruff check . && uv run ruff format --check .   # линт и формат
uv run mypy                      # strict, пакет задан в pyproject
uv run pytest                    # все тесты
uv run pytest tests/test_x.py::test_name   # один тест
```

Порядок правок: `uv run ruff check --fix .`, затем `uv run ruff format .`.

## Соглашения

- **Линт и типы строгие.** Ruff — широкий набор, mypy — `strict` с доп. кодами;
  правила, отключения (каждое с причиной) и настройки — в `pyproject.toml`.
  Проверяются и `src`, и `tests`.
- **Никаких построчных подавлений.** `noqa`, `type: ignore`, `fmt: off/skip` и
  подобного в коде нет: правило либо выполняется, либо отключается в `pyproject`
  с причиной. Это проверяет тест.
- **`Any` и `object` запрещены** в любой позиции (ruff плюс тест по AST). Если
  точный тип неизвестен — это повод его выяснить, а не расширить. Значение из
  JSON — `pydantic.JsonValue`, сужается до конкретного типа моделью у читающего.
- **Весь код — по-английски**: комментарии, докстринги и человекочитаемые строки
  (сообщения ошибок, описания инструментов и параметров, логи). Это
  переопределяет общее «текст по-русски» из `~/.claude/CLAUDE.md`. Не
  переводится функциональное (shell/ssh-фрагменты, регулярки, ключи,
  enum/`Literal`) и загружаемое извне (вывод команд, чужие страницы). Проектная
  документация (`CLAUDE.md`, `README.md`) — на русском.
- **Данные — pydantic-модели** (не dataclass); рантайм с поведением — обычные
  классы. Общие модели — в `core/schemas.py`, локальные — в `schemas.py`
  роутера, отдельно от `handlers.py`. Схемы наследуют, а не копируют поля.
- **Инструменты** несут `title`, `tags` роутера и честные `annotations`
  (подсказки клиенту). Общая семантика — через готовые пресеты; уникальный набор
  описывается у инструмента с причиной. Имена инструментов уникальны по всему
  серверу (проверяет тест).
- **Докстринг инструмента — его описание для клиента**: fastmcp берёт текст до
  `Args` как описание, `Args` — как описания параметров; всё после (в т. ч.
  `Returns`) клиент не увидит — важное писать до.
- **Именование чтения единообразно** по роутерам: «дай все» — `list_<...>`,
  «дай одну» — `get_<...>`. Обратимые операции — парой антонимов (`add`/`remove`,
  `start`/`kill`). Зеркальность имён — часть читаемости наравне со структурой.
- **Ошибки клиенту — `UserError`** (`core/errors.py`); текст уходит как есть.
  Прочие исключения не ловить — fastmcp обернёт и залогирует сам.
- **Зависимости** через uv; актуальный список — в `pyproject.toml`.

## Архитектура

Два слоя, зависимости строго вниз: **роутеры → `core`**. Роутеры друг о друге не
знают (проверяемо: нет взаимных импортов), поэтому роутер добавляется и
удаляется вместе со своим каталогом, не задевая остальных.

- **Роутер** (`routers/<name>/`) — свой `FastMCP` и ровно три модуля:
  `handlers.py` (инструменты), `services.py` (логика), `schemas.py` (модели
  ответа и локальные вокабуляры). Других модулей нет (проверяет тест). Handlers
  тонкие: делегируют в сервисы, уводят синхронную работу в поток, несут только
  метаданные и докстринг. Сервисы сами берут настройки и разрешают алиас; ошибки
  клиенту кидают тоже они, обработчики их не переупаковывают. Роутер держит свой
  жизненный цикл сам.
- **`core`** — общий низ и точка сборки: корневой `mcp` с авто-монтажом роутеров
  (перебор подпакетов `routers`, без знания их поимённо), конфигурация, ошибки,
  файлы состояния, общие схемы и утилиты. `core/utils/` — реализация, общая
  роутерам, о самих роутерах не знает.

Неизменяемые параметры и конфигурация окружения разведены по разным модулям в
`core/config/`. Документация может отставать от кода — сверяться с кодом.
