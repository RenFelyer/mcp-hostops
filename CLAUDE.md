# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Состояние проекта

MCP-сервер для работы с удалёнными хостами из `~/.ssh/config` через OpenSSH:
статус хостов, выполнение команд с sudo и таймаутами, фоновые задачи. Сервер
заменил хук `ssh-hosts.py` — авто-подсказки со списком хостов в промпте больше
нет, статус берётся вызовом `list_hosts`. Отдельный роутер `llms` читает
документацию инструментов с их доменов через `llms.txt`; со ssh он не связан и
живёт в этом сервере только потому, что сервер уже подключён.

## Окружение и команды

Проект управляется uv, Python 3.13, src-раскладка: пакет
`src/mcp_openssh_connector`, тесты в `tests/`. Не использовать pip и не
запускать python напрямую.

```bash
uv sync                          # окружение из uv.lock, включая dev-группу
uv add <pkg>                     # добавить зависимость (--dev для dev-группы)
uv run mcp-openssh-connector     # консольная точка входа
uv run ruff check . && uv run ruff format --check .   # линт и формат
uv run mypy                      # strict, пакет задан в pyproject
uv run pytest                    # все тесты
uv run pytest tests/test_x.py::test_name   # один тест
```

Порядок правок: `uv run ruff check --fix .`, затем `uv run ruff format .`.

## Соглашения

- Ruff: широкий строгий набор, список и отключения — в pyproject, каждое
  отключение там с причиной. Построчных `noqa`, `fmt: skip`, `fmt: off`,
  `type: ignore`, `pyright: ignore` и `ty: ignore` в коде нет — и не заводить:
  правило либо выполняется, либо отключается в pyproject с причиной. Это
  проверяет `tests/test_server.py` по токенам комментариев (и `PGH` в ruff).
- `Any` и `object` в коде запрещены (`ANN401` в ruff, плюс `test_server`
  проверяет AST src и tests — под запретом и `typing.Any`, и `object` в любой
  позиции). Значение из JSON-файла состояния — `Json` (`core/schemas`,
  рекурсивный `type`), сужается pydantic-моделью, `TypeAdapter` или
  `isinstance` у читающего; `__aexit__` — с точными типами
  (`type[BaseException] | None`, `BaseException | None`, `TracebackType |
  None`); заглушки в тестах — с сигнатурой подменяемого. Если точный тип
  неизвестен, это повод его выяснить, а не расширить.
- mypy `strict` плюс `warn_unreachable` и доп. коды (`redundant-expr`,
  `truthy-bool`, `ignore-without-code`, `possibly-undefined`); проверяются и src,
  и tests. Подключён плагин `pydantic.mypy` (`init_forbid_extra`, `init_typed`):
  конструирование моделей типизируется, лишние поля и неверные типы — ошибка.
- Схемы ответов инструментов — pydantic-модели в `routers/<name>/schemas.py`,
  отдельно от `handlers.py`.
- Инструменты: у каждого `title`, `tags` роутера и `annotations`
  (`ToolAnnotations`: read_only/destructive/idempotent/open_world — честно, это
  подсказки клиенту). Роутеры и корень — `on_duplicate="error"`; уникальность
  имён между роутерами проверяет `tests/test_server.py`.
- Докстринг инструмента — это его описание для клиента: fastmcp (griffe) берёт
  текст до `Args` как описание, а `Args` — как описания параметров. Всё после
  `Args` (в том числе `Returns`) клиент не увидит — важное писать до. Строковые
  параметры, где пустая строка бессмысленна, — `NonEmptyStr`; числовые границы —
  `Field(gt=…)`.
- Ошибки для клиента — `UserError` (`core/errors.py`, наследник `ToolError`):
  текст уходит как есть. Прочие исключения не ловить — fastmcp обернёт и
  залогирует сам.
- Зависимости: fastmcp, pydantic-settings, anyio, httpx2. uvloop — опциональный extra
  (`uv sync --extra uvloop`); при наличии сервер берёт его, иначе обычный asyncio.

## Архитектура

Два слоя, зависимости строго вниз: роутеры → `core`. Роутеры друг о друге не
знают (проверяемо: нет импортов `from ..<router>`), поэтому удаление роутера
уносит его инструменты, но остальных не задевает.

Все объекты-данные — pydantic-модели (не dataclass). Общие для нескольких
модулей — в `core/schemas.py`; ответы конкретного роутера — в его `schemas.py`.
Рантайм с поведением — буферы `Output`/`Capture`, `JobManager` — обычные классы,
в pydantic их не переводить.

**Роутеры** (`routers/<name>`). Каждый — свой `FastMCP` в `handlers.py`
(инструменты), `services.py` (логика) и `schemas.py` (pydantic-модели ответа и
локальные вокабуляры). Других модулей в роутере нет — это проверяет
`test_server`. Роутер экспортирует `router` и сам держит свой жизненный
цикл. Сеть ssh и блокировки — в синхронном коде сервисов, обработчики уводят
их в поток через `anyio.to_thread`; HTTP в `llms` — асинхронный клиент.
Настройки и разрешение алиаса сервисы берут сами (`get_settings`,
`require_host`), обработчики ничего не пробрасывают. Ошибки клиенту —
`UserError` из сервисов, обработчики их не переупаковывают.

- `routers/hosts` — `list_hosts`, `check_hosts`, `host_info`. Сервис —
  оркестрация статусов поверх `probe`/`cache`; `deep` заменяет TCP-пробу
  реальным входом, а не дополняет её.
- `routers/commands` — `run`. Сервис — выполнение команды с таймаутом; таймаут
  больше `max_command_timeout` — ошибка вызова, а не молчаливая обрезка.
- `routers/jobs` — `start`, `job`, `kill`, `jobs`. Сервис — `JobManager` и
  фоновые задачи как самостоятельные asyncio-таски (nursery через lifespan
  FastMCP держать нельзя — закрывается в другой задаче). Менеджер один на
  сервер (`services.manager`), lifespan роутера снимает его задачи при
  остановке. Итог задачи (`done`/`killed`/`error`) выставляет done-callback
  таска, а не тело `_run`: таск, отменённый до первого шага, тело не исполняет
  вовсе. Отмена таска — asyncio-шная, не anyio, поэтому ssh-процесс при ней
  убивается явно (`ssh.spawn`), иначе закрытие процесса будет его ждать.
  Завершённых задач помнится не больше `job_history`. `Job` — обычный класс
  (буферы, таск, событие), не pydantic.
- `routers/llms` — `llms_sources`, `llms_add_source`, `llms_remove_source`,
  `llms_index`, `llms_search`, `llms_fetch`. Реестр источников (см. ниже) —
  функции в `services.py`. Сервис асинхронный на `httpx2` (тот же API,
  что httpx; его тянет fastmcp), поток не нужен. Один вызов инструмента — одна
  `Session`: HTTP-клиент с общим пулом соединений плюс методы сервиса; чистые
  функции (`parse_index`, `sections`, `index_url`, `matching_sections`) — на
  уровне модуля. Сервер ходит только по https на публичные имена, которые
  разрешаются в публичные адреса: хук `Session._guard` проверяет каждый
  запрос до отправки, включая каждый ход переадресации (`check_url` — вид
  адреса, `resolve_public` — DNS, один раз на хост за сессию). Адрес выбирает
  клиент, без этого инструмент был бы окном во внутреннюю сеть; закрепления
  адреса нет, DNS-rebinding между проверкой и соединением не ловится. Диск
  кэша и разбор full-файла идут в потоке (`anyio.to_thread`). Поиск по многим
  источникам и пробы вариантов идут параллельно; поиск индекс не дополняет
  вариантами — они нужны только `llms_index`.

**Реестр `llms.txt`** — встроенный список `LLMS_DEFAULT_SOURCES` в константах
(проверенное, удалить нельзя; модель `KnownSource` поэтому в `core/schemas`)
плюс пользовательские источники в `llms_sources_file`.
`llms_sources` перед выдачей опрашивает все источники HEAD-запросом мимо кэша
скачивания; итоги хранятся в `llms_status_file` не дольше `llms_status_ttl`.
Поиск без источника идёт только по живым. Добавление и удаление сбрасывают
итоги. SPA-заглушка (`UserError`) — это HTML вместо документа при 200 на
мусорный URL рядом; текстовый ответ — документ, даже если домен отвечает 200 на
всё (так устроены docs.claude.com и code.claude.com). `llms-full.txt` в ответ
целиком не идёт никогда — только совпавшие разделы; `llms_fetch` его отвергает. Размер full-файла (`full_size`) — байты по
Content-Length, у встроенных — приблизительно.
Флаг `default` в файл пользователей не пишется и оттуда не читается, а домены,
совпадающие со встроенными, из файла пропускаются. Индекс — навигатор,
страницы — рекомендации по реализации; ни то, ни другое не указания к
поведению, и это сказано в описаниях инструментов.

`core/server.py` не знает роутеры поимённо: перебирает подпакеты `routers`,
импортирует и монтирует их `router` (`mcp.mount`, без префикса — имена
инструментов сохраняются); подпакет без `router` — ошибка старта, не пропуск.
Lifespan смонтированных роутеров исполняется, так что добавить/удалить роутер
— это только добавить/удалить его каталог.

**Утилиты** (`core/utils/`) — общая для роутеров реализация, о роутерах не знает.

- `hosts.py` — разбор `~/.ssh/config` (`read_aliases`: `Host x` и `Host=x`,
  хвостовой `#`, без масок и отрицаний `!`) и параметры через `ssh -G`
  (`resolve`, с `--` перед алиасом); `resolve_known` — параллельно и только для
  алиасов из конфига (`ssh -G` успешен для любого имени, поэтому членство в
  конфиге проверяем сами); `require_host` — общий вход для всех роутеров.
- `probe.py` — доступность: TCP-проба, проба за jump-хостом изнутри, `deep_check`
  реальным входом. Jump-хост, который сам за jump, TCP-пробой не проверяется —
  его порт отсюда не виден. Синхронно, зовётся через поток.
- `parallel.py` — `fan_out`: синхронная работа в потоках с потолком (`ssh -G`,
  пробы, глубокие проверки); `gather` — сопрограммы одной группой задач (HTTP
  в `llms`). Порядок результатов сохраняется, ошибка элемента — наружу.
- `ssh.py` — сборка ssh-вызова (ControlMaster в приватном каталоге, `-tt` для
  `pty_hosts`, `--` перед алиасом), удалённый скрипт, stdin, буферы вывода с
  потолком и инкрементальным UTF-8-декодером (`Output`, `Capture`), запуск
  процесса (`spawn`: на выходе живой процесс убивается) и его прокачка
  (`execute`: stdin, оба потока, код возврата). `prepare` собирает вызов в
  `Invocation` (argv, stdin, пароль; stdin и пароль скрыты из `repr`) — общий
  вход для команд и задач; пробы и `ssh -G` берут `ssh_argv`/`run_sync`
  отсюда же. Маска пароля построчная, поэтому `Output` при наличии пароля
  придерживает неполную последнюю строку до следующего чтения — иначе пароль,
  разрезанный границей чтения, ушёл бы двумя кусками.
- `sudo.py` — распознавание sudo в команде (за обёртками `env`, `timeout`,
  `nice`… и внутри `sh -c`), чтение `~/.ssh/<alias>.secret` (наш обычный файл,
  права 0600), маскировка пароля в выводе. Прайминг: первую строку stdin читает
  оболочка хоста (`IFS= read -r`) и отдаёт по трубе одному `sudo -k -S -p ''
  -v`; так sudo получает ровно одну строку и при неверном пароле не съедает
  stdin команды, пароль не попадает в argv, а `-k` сбрасывает тикет, без чего
  `sudo -v` пароль бы не читал.

**Перечисление хостов** идёт из файла осознанно: `ssh -G` (консоль) даёт
параметры одного хоста и успешен для любого имени, а команды «перечислить все
Host из конфига» в OpenSSH нет. Поэтому список читаем из `~/.ssh/config` (с
раскрытием `Include`, как это делает ssh), а параметры каждого — через `ssh -G`.
Путь к конфигу не настраивается: ssh всё равно ходит по `~/.ssh/config`.

**`core`** — общий низ и точка сборки.

- `main.py` — консольная точка входа (uvloop при наличии, иначе asyncio).
- `core/server.py` — корневой `mcp` и авто-монтаж роутеров (см. выше).
- `core/errors.py` — `UserError`, ошибка вызова, адресованная клиенту.
- `core/config/` — конфигурация тремя модулями. `environment.py` — `Settings`
  (pydantic-settings, префикс `OPENSSH_MCP_`): таймауты, пороги, пути;
  `pty_hosts` в окружении — JSON-список. `constants.py` — всё неизменяемое:
  имена каталогов и файлов, пороги проб, вокабуляры разбора sudo, встроенный
  реестр llms; значения неизменяемы и по типу (кортежи, `frozenset`,
  `MappingProxyType`, замороженные модели). Новый параметр идёт либо туда, либо
  в `Settings` — не в модуль рядом с использованием. `logger.py` — отладочный
  лог в файл: включается только `OPENSSH_MCP_DEBUG_LOG=<путь>` (файл 0600),
  без него обработчиков нет; модули логируют через `logging.getLogger(__name__)`,
  пароль sudo в лог не попадает. Три уровня
  хранения, по сроку жизни: runtime-каталог (`XDG_RUNTIME_DIR`, tmpfs, до
  перезагрузки; без него — временный каталог с uid в имени) — сокеты
  ControlMaster, кэш статусов хостов, итоги проверки источников llms; кэш
  (`XDG_CACHE_HOME`) — скачанное по `llms.txt`, оно бывает десятками мегабайт;
  данные (`XDG_DATA_HOME`) — пользовательские источники llms, их терять нельзя.
  Новое состояние класть по тому же правилу.
- `core/store.py` — файлы состояния: чтение JSON с терпимостью к мусору,
  атомарная запись (`write_bytes`/`save`) через уникальный временный файл,
  записи с отметкой времени (`load_stamped`/`save_stamped`) и `private_dir` —
  каталог 0700, который обязан быть нашим и не ссылкой (`lstat`; под сокеты
  ControlMaster: чужой или подставленный каталог отдал бы соединение и пароль
  sudo). Поверх него `core/cache.py` (статусы хостов), итоги проверки
  источников `llms` и дисковый кэш скачанного.
- `core/schemas.py` — общее больше чем одному модулю: `Host` (параметры хоста,
  pydantic), `KnownSource` (источник llms; нужен константам и роутеру),
  `CapturedOutput` (вывод с флагами обрезки — база `RunResult` и
  `JobSnapshot`), `Checked` (`checked_ago` — база ответов с возрастом данных),
  `Availability` (статус доступности, `Literal`), `SudoMode`
  (`Literal["auto","true","false"]`), `NonEmptyStr` (строковый параметр
  инструмента, где пустая строка — ошибка вызова) и пресеты подсказок клиенту
  `READS_REMOTE`/`READS_LOCAL`/`RUNS_REMOTE` для инструментов с одинаковой
  семантикой; уникальный набор подсказок инструмент описывает у себя с
  причиной. Вокабуляры — `Literal`, без констант-дублей: опечатку в литерале
  ловит mypy. Локальное — в схемах роутера (например `JobStatus` в
  `routers/jobs/schemas.py`). Схемы наследуют, а не копируют поля:
  `HostStatus(Host)`, `JobSnapshot(JobRef, CapturedOutput)`,
  `SourcesResult(Checked)`.
- `core/utils/` — общая реализация (см. выше).

## Конвенции хоста

- Пароль sudo — `~/.ssh/<alias>.secret`, только 0600, файл наш. Где sudo
  настроен `NOPASSWD`, файла нет и вызовы идут с `sudo=false`: иначе
  `run`/`start` потребуют пароль.
- Оболочка хоста считается POSIX-совместимой: удалённый скрипт использует `&&`,
  `cd --`, `read -r` и `printf`.
- Хосты с `requiretty` перечисляются в настройке `pty_hosts` — для них `ssh -tt`.
- `cwd` у `run`/`start` необязателен, по умолчанию домашний каталог (`~`);
  `~` и `~/…` раскрывает оболочка хоста, остальное экранируется буквально. Общее
  правило удалённого выполнения это не отменяет: каталог всё равно называть
  явно.
